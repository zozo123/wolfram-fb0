wolfram-fb0

By Yossi Eliaz · experiment · May 2026

An experiment: an oracle loop asks a 1B local model (gemma3:1b via Ollama) to write pure x86_64 NASM that renders Rule 30, then pixel-diffs it against a Python reference, all inside an islo.dev VM. The first 3 iterations (24 May 2026) did not produce a correct image. The animation below is drawn by JavaScript from the reference algorithm.

Why a VM, not a container

Most AI coding sandboxes are containers. The full design needs three things containers usually can't give you:

  • Run bpftrace against kprobes — needs real kernel access.
  • Open /dev/fb0 — there's no framebuffer device in a container.
  • Boot a nested qemu-system-x86_64 on real virtualization — needs KVM.

That is why the experiment runs in an islo.dev VM, which has its own kernel. So far only the assemble, run and pixel-diff loop has run there; the framebuffer and eBPF steps are planned.

The build, in five acts

  1. Provision — islo use wolfram-fb0 provisions the Linux VM described in islo.yaml: nasm, qemu, bpftrace, Ollama with gemma3:1b, and opencode.
  2. Code — harness/runner.py prompts gemma3:1b via ollama run, extracts the last code block and writes src/rule30.s (harness/loop.py, which drives opencode, has no committed run yet).
  3. Judge — An oracle in the same sandbox assembles each iteration, runs it in --ppm mode, pixel-diffs it against a Python reference, and records binary size. The prompt escalates on a fixed schedule (few-shot, then scaffold-fill); scores are recorded, not yet fed back.
  4. Boot — Planned, not yet run: qemu-system-x86_64 boots a small Linux image straight into the agent-built ELF on a framebuffer, and bpf/trace.bt traces its syscalls and framebuffer writes.
  5. Share — Planned, not yet run: islo share exposes the framebuffer stream and the eBPF event stream (harness/bridge_fb.py, harness/bridge_bpf.py) so the panes below can render them.

Run it

Runs on islo.dev (the author's employer); needs an islo account.

islo use wolfram-fb0 --source https://github.com/zozo123/wolfram-fb0
# inside the sandbox: the loop that produced the committed iterations
python3 harness/runner.py --target rule30 --max-iters 8

Running it on your own Linux machine needs nasm, ld, qemu-system-x86_64, bpftrace, Python 3 (pillow, numpy) and Ollama with gemma3:1b.
